Data Centre Library with GLPI

Learn to document and manage server rooms, racks, power and cabling using the open-source GLPI ITSM / asset management tool.

What is GLPI and why use it for a data centre?

GLPI (Gestionnaire Libre de Parc Informatique) is a free, open-source IT Service Management (ITSM) and IT Asset Management (ITAM) web application. Alongside helpdesk tickets, contracts and licences, it includes a dedicated data centre module for documenting physical infrastructure.

What you can manage

  • Data centres and the server rooms inside them, drawn as a grid floor plan
  • Racks with a visual front/rear elevation (U-by-U)
  • Servers, network equipment, enclosures (blade chassis), PDUs and passive devices (patch panels, cable managers)
  • Cables and network ports between devices
  • Power and weight capacity per rack, plus financial, warranty and contract information per asset

The GLPI data centre hierarchy

Data centre→ Server room→ Rack→ Device (server, switch, PDU…)

Learning outcomes

  1. Install and secure a GLPI server
  2. Model a data centre, its rooms and rack layout
  3. Place devices in racks using models with correct U height
  4. Track power capacity, cabling and network connections
  5. Feed GLPI automatically with the GLPI Agent

Installing GLPI (lab server)

GLPI is a PHP application backed by MySQL/MariaDB. For a lab, a single Linux VM (e.g. Ubuntu Server or Debian) is enough.

Always check the official installation guide for the exact PHP and database versions required by the GLPI release you download.

Step 1 – Install the web stack

sudo apt update
sudo apt install -y apache2 mariadb-server php php-{mysql,curl,gd,intl,mbstring,xml,zip,bz2,ldap,bcmath} libapache2-mod-php

Step 2 – Create the database

sudo mysql
CREATE DATABASE glpi CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'glpi'@'localhost' IDENTIFIED BY 'ChangeMe-Strong!';
GRANT ALL PRIVILEGES ON glpi.* TO 'glpi'@'localhost';
FLUSH PRIVILEGES;
EXIT;

Step 3 – Download GLPI

Download the latest release archive from github.com/glpi-project/glpi/releases and extract it:

cd /var/www
sudo tar -xzf ~/glpi-<version>.tgz
sudo chown -R www-data:www-data /var/www/glpi

Step 4 – Run the installer

Either open http://<server-ip>/glpi in a browser and follow the wizard, or use the command line:

cd /var/www/glpi
sudo -u www-data php bin/console db:install -H localhost -d glpi -u glpi -p 'ChangeMe-Strong!'

Step 5 – First login and hardening

  • Default accounts: glpi/glpi (super-admin), tech/tech, normal/normal, post-only/postonly. Change all passwords or disable unused accounts immediately.
  • Delete the install/install.php file once installation is finished.
  • Point the web server's document root at GLPI's public/ directory (GLPI 10.0.7+) and serve it over HTTPS.

Things to note

  • U1 is at the bottom; heavy kit (UPS, storage) goes low.
  • Leave blank U for airflow and future growth – use blanking panels physically.
  • Items can be marked front or rear and full or half depth.
  • Vertical (0U) PDUs can be attached to the rack's left/right side.
  • GLPI prevents placing two items in the same U space.

Devices, models and power

1. Create models first

Rack placement depends on the model. Under Setup > Dropdowns > Models set, for each model:

  • Required units (U height) and whether it is half rack width
  • Depth (full, ¾, ½, ¼)
  • Power connections and power consumption (W)
  • Weight and optional front/rear pictures for a realistic rack view

2. Asset types that can live in a rack

3. Place a device

  1. Open the rack and switch to the Racks (elevation) tab.
  2. Click a free U slot (or the + icon) and pick the item type and item.
  3. Choose position, orientation (front/rear) and confirm.
  4. Drag-and-drop in the elevation to move items later.

4. Power planning

Link PDUs to the rack and record the power plugs. Compare the sum of model power consumption against the rack's Max. power to avoid overloading a circuit. A common rule of thumb is to plan for no more than ~80% of a circuit's rated capacity.

Cabling and network ports

Network ports

Each computer and network device has a Network ports tab. Ports can be created manually or by inventory, with MAC address, IP, VLAN and speed.

Cables (GLPI 10+)

Menu: Assets > Cables. A cable records:

  • Endpoint A and Endpoint B – asset + socket/port on each side
  • Cable type (Cat6, OM4 fibre, power…) and cable strand
  • Colour, Inventory number and state

Sockets for patch panels and wall outlets are managed under Setup > Dropdowns > Management > Sockets.

Automatic inventory with the GLPI Agent

Since GLPI 10, inventory is native: the GLPI Agent sends hardware and software data straight to GLPI, so you don't have to type serial numbers, CPUs, RAM, disks or NICs by hand.

Enable inventory on the server

Administration > Inventory → tick Enable inventory and save.

Install the agent on a Linux server

# Debian/Ubuntu (download the installer from the GLPI Agent releases page)
sudo perl glpi-agent-<version>-linux-installer.pl --server=https://glpi.example.com/ --install

# Force an inventory immediately
sudo glpi-agent --server https://glpi.example.com/ --force

Windows

Run the MSI installer and enter the server URL, or deploy silently:

msiexec /i GLPI-Agent-<version>-x64.msi /quiet SERVER="https://glpi.example.com/" RUNNOW=1

Network discovery and SNMP

Switches, PDUs and UPS units usually can't run an agent. Use the agent's netdiscovery and netinventory tasks with SNMP credentials to inventory them remotely.

After the device appears in GLPI, you only need to assign it a model and place it in the correct rack U position.

Security and best practice

A data centre inventory is a map of your most critical systems – protect it like one.

Secure the GLPI server

  • Serve GLPI only over HTTPS; restrict access to admin networks or VPN.
  • Change or disable all default accounts; enforce strong passwords and enable two-factor authentication (TOTP) where your version supports it.
  • Integrate with LDAP/Active Directory and use GLPI profiles and entities for least-privilege access.
  • Keep GLPI, PHP and plugins up to date – follow GLPI security advisories.
  • Ensure the config/, files/ and marketplace/ directories are not reachable from the web.
  • Back up the database and files/ directory regularly and test restores.

Data quality habits

  • Update GLPI as part of every change ticket (install, move, decommission).
  • Use the Status field (In production, Stock, Retired) consistently.
  • Run periodic physical audits: compare rack photos with GLPI elevations.
  • Use the History tab to see who changed what and when.

4. Import your layout

Describe rooms and racks in layout/racks.csv and devices with their U position in layout/devices.csv, then run:

python3 scripts/import_layout.py --url http://localhost --user glpi \
    --racks layout/racks.csv --devices layout/devices.csv
Always fill in the serial number. GLPI links agent and SNMP inventory to existing assets by serial or UUID, not by name. Without it you get a duplicate asset.

5. Collect devices automatically

The collector container scans your network on a schedule and sends what it finds to GLPI. Nothing has to be installed on the devices. Configure it in collector/collector.conf:

  • SNMP ranges: switches, routers, firewalls, PDUs, UPS, storage, printers (read-only community or SNMPv3)
  • SSH / WinRM: Linux and Windows servers, using an inventory account
  • VMware: ESXi hosts and vCenter, using a read-only user
docker compose restart collector               # apply the settings
docker compose exec collector collect.sh once  # collect now

The Inventory dashboard (http://<server>:8080/viewer/inventory.html) shows the results: summary tiles, collection status, charts, a network map built from switch LLDP/CDP data, and a searchable device table with CSV export.

Prefer an agent? install-agent-linux.sh and install-agent-windows.cmd are still included.

6. Watch device status (Grafana)

Every device in GLPI that has an IP address is pinged every 30 seconds by Prometheus and the Blackbox exporter. The Status tab shows the Grafana Device status dashboard: how many devices are up and down, which are down and for how long, an UP/DOWN history per device, 24-hour availability and ping times. Extra checks (SSH, web pages, TCP ports) go in monitoring/manual/*.yml.

A second dashboard, Network & hardware, polls every switch, router, firewall, load balancer, iLO and iDRAC over SNMP. It shows ports that are down, traffic and errors, switch and router CPU, Sophos HA state and resources, and server hardware health such as power supplies, temperatures and drives.
