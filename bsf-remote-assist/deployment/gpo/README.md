# BSF Remote — Domain/GPO Deployment

## Recommended deployment model

1. Administrator creates a device enrollment record in BSF Remote.
2. The portal returns a one-time enrollment token.
3. Place the generated `DeviceId` and token into the deployment mechanism for the intended PC or OU.
4. Deploy `Install-BSFRemoteAgent.ps1` through Computer Configuration → Windows Settings → Scripts (Startup), or a Scheduled Task GPO.
5. Deploy the official MeshCentral agent separately using the exact installer/download URL generated by your own MeshCentral server and device group.
6. Approve the device in BSF Remote before technicians can connect.

## Important

Do not put one enrollment token into a domain-wide GPO. Enrollment tokens are device credentials. For bulk deployment, generate unique device enrollment records/tokens and distribute them through a secure provisioning mechanism, or implement a domain-machine bootstrap endpoint that authenticates the machine with a dedicated AD service identity and issues a single-use token.

Do not download a random MeshCentral binary from the public internet during GPO execution. Host the exact tested agent package internally and verify its hash/signature before deployment.

## GPO settings

Computer Configuration → Policies → Windows Settings → Scripts → Startup

Run PowerShell with:

`powershell.exe -NoProfile -ExecutionPolicy Bypass -File \\DOMAIN\SYSVOL\DOMAIN\scripts\BSFRemote\Install-BSFRemoteAgent.ps1 ...`

Prefer a dedicated security group/OU for the pilot before expanding deployment.

## Pilot procedure

1. Pilot OU: 5–10 PCs.
2. Run `gpupdate /force` on a pilot PC.
3. Verify `C:\ProgramData\BSFRemote\install.log`.
4. Verify the device heartbeat in the portal.
5. Verify MeshCentral agent appears in the expected MeshCentral device group.
6. Approve the device in the portal.
7. Test technician authorization, unattended step-up MFA, remote desktop, terminal and file transfer.
8. Only then expand the GPO scope.
